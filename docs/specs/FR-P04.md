# FR-P04 整備記録の入力

- 優先度：Must（段階1）
- タスク：T-05
- 使うAPI：なし（送信はFR-P05）

## 目的

整備記録を入力し、確認画面で内容を見せてから送信へ進める。

## 入力項目

| 項目 | 形式 | 必須（案） | APIのフィールド |
| --- | --- | --- | --- |
| 記録の種類 | 修理／部品交換／点検 | 必須 | `recordType` |
| 作業日時 | 日時 | 必須 | `workedAt` |
| 修理箇所 | 未決（選択肢か自由記述） | 修理・部品交換で必須 | `content.repairArea` |
| 使用パーツ | 名前＋純正／互換（複数可） | 修理・部品交換で必須 | `content.parts` |
| 点検結果 | 未決 | 点検で必須 | `content.inspectionResult` |
| メモ | テキスト | 任意 | `content.memo` |

## 受け入れ基準

1. 上の6項目を入力できる
2. 記録の種類に「訂正」「取り消し」は出さない（FR-P07で扱う）
3. 必須項目が空のまま確認画面に進めない。必須の範囲は上の表（案）に従う
4. 作業日時に未来の日時は入れられない
5. メモは500文字まで（案）。入力欄の近くに「お客様の名前や連絡先は書かないでください」と表示する
6. 入力エラーは項目のすぐ下に表示し、エラーがなければ確認画面で入力内容を一覧で見せる。確認画面から入力に戻ると内容が残っている
7. 入力検証は `src/lib/schemas/` のZodスキーマ1つで行い、画面とサーバー側の両方で同じスキーマを使う

## 日時の扱い

- 画面では日本時間で入力・表示する
- Goに送るときはUTCの `Z` 付き・秒まで（例 `2026-11-10T05:30:00Z`）に変換する。変換は1つの関数にまとめ、単体テストを書く
- 理由：ハッシュの一致に関わるため（`requirements.md` 5章）

## やらないこと

- 下書きの保存
- 写真の添付
- 部品の在庫や型番のマスタ管理

## テスト

- E2E：基準1、2、3、6
- 単体：基準4、5、7、日時の変換

## 確認が必要な点

- 必須項目の範囲（上の表は案）
- 修理箇所・点検結果を選択肢にするか。選択肢にするならその一覧
- 決まるまでは自由記述のテキストで作り、選択肢に変えやすいようにスキーマに集約しておく
