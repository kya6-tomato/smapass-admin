# FR-P03 端末の指定（コード・QR）

- 優先度：Should（段階2）
- タスク：T-09（手入力）、T-10（QR）
- 使うAPI：`POST /device-sessions`
- 着手条件：段階1（T-08）が完了していること

## 目的

アプリが表示する期限付きの手入力コードかQRで端末を指定し、その端末に一定時間だけ書き込めるようにする（D2）。持ち主の同意と、事業者が実物を手元に持っていることの裏付けを兼ねる。

PCのカメラでのQR読み取りは会場で失敗しやすいので、手入力を先に作る。

## 受け入れ基準

1. アプリの手入力コードを入れると、その端末が記録先になり、FR-P02と同じ表示で記録先を出す
2. コードは期限5分・1回限り（案）。期限切れ（`code_expired`）、使用済み（`code_used`）、誤り（`code_invalid`）でそれぞれ別のメッセージを出す（文言は `api-contract.md`）
3. 誤入力の回数制限（案：1コード5回で失効）はGo側で判定し、サイトは `too_many_attempts` のメッセージを出す。サイト側で回数を数えない
4. 記録先が決まったら、書き込みできる残り時間（`writableUntil` まで）を表示する。時間切れになったら送信ボタンを押せなくし、コードの再入力を促す
5. （T-10）QRを読み取った結果は、手入力と同じ処理に渡す。カメラが使えない・読めないときも手入力で続けられる

## やらないこと

- アプリ側のコード・QRの表示（アプリの担当）
- コードの生成・判定（Goの担当）

## テスト

- E2E：基準1〜4（モック使用）
- T-10は会場と同じPC・カメラで手動確認する

## 確認が必要な点

- コードの桁数と文字の種類（数字だけか英数字か）。入力欄の形に影響する
- QRに入れる中身（コードそのものか、URLか）
- QR読み取りの方法（ライブラリかブラウザ標準のBarcodeDetector APIか）はT-10で選ぶ
